## 2026-09-15 腰部起点修正

以下增量优先于后文历史启动状态。新版需要安全结束后完整重启应用，不能只重开 GUI；本轮没有停止或重启现场 owner。

- 仅“规划腰部恢复”改变起点策略：实测关节仍原样归档并用于静止、新鲜度和起点误差检查；指令从网关原保持参考直接五次插值至目标，不再先返回实测角。两臂保持参考不因腰测试而重新捕获。

- 两模式的 Kp/Kd/Ki、50 Hz 腰字段更新、100 Hz 发包及原速度/加速度/jerk、STOP/温度/力矩保护均未调高或放宽。
- 原运动 CSV 格式不变。新增 `logs/endpoint_motion/waist_commands/同名CSV`，逐次记录发布调用返回的单调时间、序号、模式、参考 q/dq、真实提交给 publish 的 `sent_q/dq/tau/kp/kd`、实测 q/dq/tau_est、积分和 `start_blend_s`。这不是电机收包 ACK。原 CSV 的 `command_dq` 不能当作官方模式实际发送的 dq。
- 本次比较只做无接触的绝对角度 `0° -> 20° -> 0°`，每段重新规划、核对净空并单独执行，待静止保持后才切另一种模式重复。两次保持屏幕页速度/加速度比例一致；没有自动循环或自动重试。新计划状态含“腰部连续恢复”。
- 保持参考本来就是 20° 时，重复 20° 只保持，不为消除残差而先退回实测角；若不满足原到位门槛仍会失败，未放宽容差。

## 本次关机后的完整启动流程

本次已关闭旧控制器、面板和整套应用服务；没有自动启动新服务或执行运动。
新网关编译后由下一次完整启动加载，不能仅重开 GUI。

1. 固定双脚和额外支撑，确认手臂/躯干净空。按原厂流程上电并完成运控初始化，
   人工完成原来的 R2+A 流程；恢复电脑与机器人网络、相机和手的连接。
2. 启动完整应用（脚本已 source 两套 ROS 环境，勿另开旧控制器）：

   ```bash
   cd /home/syf/g1_upper_body_ws
   bash scripts/start_task_panel.sh
   ```

   若报 `192.168.123.99 does not match an available interface`，先恢复原有网络接口地址；
   不是通过重复启动控制器解决。启动不自动 ARM，旧启动点的授权也不自动恢复。
3. 在原面板重新确认并捕获本次会话启动点，然后显式 ARM，等待 `ARMED_HOLD`。
   屏幕页应显示腰目标 50 Hz、统一发包 100 Hz；未知模式表示没有加载新版网关。
4. 如复用旧工位，先加载配置。上次六点自动备份：
   `data/task_sessions/20260914_154733_881763/screen_autosave/config.json`。
   允许明确确认后迁移仅腰限幅发生变化的旧端点；不会恢复对齐和执行授权。
5. 需要对比腰控制时，在屏幕页选择“现有控制”或“官方 PD”，点“应用腰控制模式”。
   可在未 ARM 或健康静止的 `ARMED_HOLD` 下切换，**无需重启、无需重新 ARM**。
   双手先离开物体；保持中采用 1 秒五次平滑参数过渡，等待网关“过渡中”消失。
   切换不规划角度运动，但平衡误差随增益变化可能引起小幅实际调整。
6. 对比可用相同速度参数，分别执行 `0° -> 5° -> 0°`：输入目标、
   “规划腰部恢复”、检查 RViz 和现场净空、勾选 Path clear、点击执行。
   每段结束等待静止保持，再切换模式重做同一组角度。每次切换清除旧计划和预演确认。
   `waist_result.json` 记录本次模式、目标、实测角度和误差；不保证官方 PD 更丝滑。
7. 选定模式后恢复到 0°。静止且腰角为 `0° ±0.5°` 时刷新点云，
   首次框选与屏幕固定的参考物；旧参考没有腰角信息时重建。
   RViz 核对参考/当前点云的表面、边缘与物理标记，确认本次工位对齐。
8. 新示教：进入“双臂＋腰导纳示教”，等待 `TASK_ADMITTANCE`，
   依次静止记录屏幕外 T 和屏幕表面 P1-P5；拟合平面、确认朝外法向、导出。
   复用有效六点则不必重录，但须重新核对法向及工位。
9. 指尖离屏并静止后“退出导纳，原地保持”；规划移动到 T，检查预览后执行。
   不需手动复刻 T。然后两个分离点各做一次“模型偏移预演”，人工确认对位结果。
   模型 10 mm 偏移不是实测间隙，必须观察现场，不能当作不会触屏的保证。
10. 选择“回放示教触点”，逐点规划、检查、执行；依据屏幕实际响应确认成功。
    首版没有压力控制或额外压入。结束后导出配置，按原流程回到关机姿态再关闭应用。

默认每次完整启动采用现有控制；加载几何配置不自动切换硬件控制模式。
导纳/运动/释放/故障中不允许切换，拒绝时会说明原因，不自动 STOP、ARM 或复位。
锁存静默时先查明原因，不能用切换模式绕过保护。

## 首次示教

1. 按现有流程人工确认/捕获会话启动点、ARM。新功能不自动执行这些操作。
2. 固定双脚站位及额外支撑，保持屏幕和参考物相对固定。右手食指伸直、其余手指收拢。
   本页不自动摆手型。原手 DDS 必须可用，模型和原网关必须支持腰 yaw。
3. 如需复用，先“加载”工位。仅腰限幅 35° → 45° 的旧模型在明确确认后可迁移端点；
   其他模型、标定、手映射差异不放行。迁移不改变原关节和 FK，不恢复授权。
4. 先完成工位对齐：查看当前实测腰角。若不是 0°，目标设为 0°，点击“规划腰部恢复”，
   确认双手脱离和转动净空，检查 RViz，勾选 Path clear，再执行。
   必须先处于 ARMED_HOLD；若在导纳中，先“退出导纳，原地保持”。不会自动 ARM。
5. 腰处于 0° ±0.5° 并静止后“刷新当前点云”，首次“框选并保存参考物”。
   选择与屏幕固定的物体，包含边缘/角点，不包括手臂。金色是参考，青色是新快照。
   旧参考没有腰角记录时必须重建；复用有效参考时只需刷新当前点云并核对。
6. 核对物理标记、支撑、表面和边缘，“确认本次工位对齐”，然后才开始示教。
7. 点击“进入双臂＋腰导纳示教”；等待明确显示 `TASK_ADMITTANCE` 再拖动。
   正常进入腰导纳保留刚才的工位对齐，清除旧路径及预演确认。此后示教允许腰转动。
8. 在屏幕外侧拖到公共过渡点，选 T，静止后点击“记录选中端点”。
9. 依次把指尖带到 P1–P5 的屏幕表面，确认触碰但不主动继续压入，静止后记录对应行。
   记录的是实测关节和手反馈，不是下发目标，也不记录拖动过程。覆盖已有点需要确认。
   记录前和读取手反馈后都检查关节限幅；拒绝时指出点、关节、角度和范围，不覆盖原点。
10. 点击“拟合屏幕平面”，查看残差和 RViz 绿色箭头；必要时“反转法向”，确认箭头朝屏幕外。
   最大 FK 拟合残差超过 5 mm 或五点近共线时拒绝确认。5 mm 是软件复核门槛，不是精度保证。
11. “导出”配置。记录端点/替换参考也自动备份到当前会话 `screen_autosave/config.json`。

固定端点、平面和两组点云通过原 `/g1/vision_task_preview` MarkerArray 显示，frame 为 `pelvis`。
沿用原 RViz 的 Task preview 显示，不创建控制节点或修改规划场景。
当前点云是静止时采集的快照，不是实时流；移动站位后必须再次采集。
点云沿用现有相机及 B/C 变换；原始关节记录不叠加 A/B/C 偏移，法向路径采用记录时冻结的有效 TCP。

## 单点试运行与点击

1. 手动将指尖脱离屏幕，静止后点击本页“退出导纳，原地保持”。无需手动复刻 T。
   点击“规划移动到 T（当前姿态 → 公共点）”，确认指尖已脱离、站位和支撑未变、回程路径净空；
   查看 RViz 预览，勾选 Path clear，再点击“执行移动到公共点 T”。
   此操作从当前实测关节出发，只移动右臂和腰到所录 T，不要求事先匹配 T，不执行触屏。
   只需要已录 T，不要求先录满五点或完成点云确认；也不因此授予工位或点击授权。
   原 session 启动点与 T 是不同概念。没有新增碰撞检测，不能从仍接触屏幕或未知净空的位置盲目回点。
2. 到 T 保持后，选择一个 P 点及“模型偏移预演”，点击“规划单点循环”。当前右臂/腰必须匹配 T；
   左臂不要求复刻示教时的姿态，而是保持本次实测关节值；腰转动仍会带动躯干及左臂。
3. 核对 RViz 路径和现场净空，勾选原窗口的 Path clear，再点原执行按钮。
   一次只执行选中点：T -> 外侧接近位置 -> 法向接近 -> 额外驻留 -> 法向撤离 -> T。
   转场使用右臂＋腰，法向段腰指令固定为该点的示教值，手型不自动改变。
4. 观察无接触对位后点击“对位 / 点击成功”或“失败”。选择另一个相隔至少 20 mm 的点重复核对。
   同一点的重复试运行只计一个位置。两个分离位置均经人工确认后，才允许“回放示教触点”。
5. 触点回放结束只显示轨迹完成，必须依据屏幕实际响应再确认点击结果；失败不自动重试。

默认外侧距离 30 mm、试运行离屏距离 10 mm、法向速度上限 5 mm/s、额外驻留 0.15 s、
速度/加速度比例 0.15。软件范围见 `task_screen_teach.py`；额外进给只能为 0。
正常到位等待及手反馈读取会增加接触附近的实际停留时间，驻留参数不等于总接触时间。
法向速度按规划 FK 的密集插值样本检查，不是实际指尖速度测量。
10 mm 是 FK 模型偏移，不是物理离屏测量；FK 有误差时仍可能实际接触。

## 腰部恢复和参数链

- “腰部恢复目标”可指定角度；“目标设为 0°”仅改输入，不执行运动。
- “规划腰部恢复”不要求 T/P 点或工位对齐，必须先有会话启动点和健康静止保持。
- 只改变腰 yaw，双臂保留当前保持参考；实测状态另作安全核验，躯干和双臂仍会一起在空间中转动。
  不做碰撞查询，由操作者确认净空。使用单段五次平滑轨迹，起止速度/加速度为零。
- 腰模型/网关限幅一致为 ±45°；保留 0.02 rad 余量，可规划约 ±43.854°。
- 完成腰恢复后按不大于 0.5° 的到位误差等待并记录 waist_result.json。
  对齐/采图还会独立检查 0° ±0.5°，普通点击循环的到位参数不被扩大。
- 屏幕和腰恢复使用屏幕页自己的 velocity/acceleration 比例，进入原 Session ticket，
  再由 task_motion_limits 和密集插值验证进行定时。不是上方通用 Velocity 控件的数值。
- task_planning.yaml 的 arm_velocity_rad_s=0.40、waist_velocity_rad_s=0.35 作为基础上限，
  规划时还取当前网关允许值与配置的较小值。50 Hz 腰更新仍保留每条指令 0.006 rad
  步长保护，网关腰上限取 `min(0.35, 0.006*50*0.95)=0.285 rad/s`。
  默认比例 0.15 下为 0.04275 rad/s（约 2.45°/s），加速度上限
  `1.5*0.15=0.225 rad/s²`；实际整段还可能更慢。两种模式采用相同上限便于对比。
- 法向段额外受 speed_mm_s 限制并固定腰指令；Session 管理起点、反馈、STOP 和授权，
  原网关仍以配置的 100 Hz 插值并执行跟踪减速和原保护。
- 腰正常目标更新为 50 Hz，统一 `/arm_sdk` 包和双臂保持 100 Hz，中间包复用腰字段。
  接管渐变、STOP、导纳及异常恢复期间绕过缓存，按 100 Hz 及时更新；不新增腰独立发布者。
- 官方 PD 移植自本机 `unitree_ros2/example/src/src/g1/high_level/g1_arm_sdk_dds_example.cpp`：
  `control_dt=0.02`、腰 `Kp=240/Kd=6`，稳态 `dq=0/tau=0`，无额外积分/前馈。
  只移植策略，不运行示例中的自动摆臂/转腰动作；接管和导纳采用平滑混合，异常沿用原处理。
  原模式增益仍来自原配置，屏幕页显示网关确认的模式及实际缓存 Kp/Kd。
- 控制定时器独立于默认回调组，状态共享锁仍保留；
  诊断及运动 CSV 新增单调时钟 control_gap_ms，不能据此保证硬实时或实际运动已丝滑。

## 停止与重新使用

- 面板顶部“检查状态并解除锁存 / STOP”：由操作者点击，网关重新检查当前反馈、
  电机安全状态、运控服务及 L2+B 是否松开。正常才解除，失败显示网关原因。
  对未 ARM 且无命令发布者的锁存或任务 STOP 状态开放；使用带 STOP 编号的
  reset_task 接口，复位期间的新 STOP 不会被清除。旧网关不会回退到旧复位接口。
  成功后还需收到同一编号的 UNARMED、无 STOP 反馈才更新面板；
  启动点保留，旧计划/对齐/预演授权失效。不会自动 ARM 或恢复运动。
- 原红色 STOP 始终保留。取消当前计划并按原网关流程保持/导纳；不是立即失能。
- 受阻、跟踪/反馈/网关异常触发原停止流程，不自动撤离、不自动回 T、不重试。
  先确认机器人状态、脱离接触并恢复静止保持，再由操作者明确规划/执行移动到 T。
  不能把关节到位当作独立触屏测量。
- 更改站位、支撑或屏幕位置后，先点“站位 / 支撑已改变”，重新采集/对齐，并做两个分离点核对。
  无外部定位传感器时，软件不能自动识别底座相对台面的位移。
- 加载配置不会恢复工位确认、试运行确认或任何执行授权。普通 STOP、异常锁存、站位改变、
  替换参考和修改标定会清除工位确认；重新对齐须回到腰 0° 并刷新点云。
  正常进入腰导纳、记录点、拟合/确认法向和修改路径参数保留工位确认，但清除预演/旧计划。
- 模型、有效 TCP、A/B/C 或相机标定不匹配时拒绝复用。恢复同一配置或新建工位重新示教；不静默重定位旧点。
- 导出目录中的 `config.json` 和 `reference_<hash>.npz` 必须一起保留。JSON 最后原子写入，参考点云有校验和。
  无点云的未完成示教也可保存；不能因此获得工位执行确认。
