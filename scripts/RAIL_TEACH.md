# 固定滑轨右手推拉（2026-09-17）

入口：现有任务面板的“滑轨推拉”页。不使用视觉，不启动另一套控制器。
准备位复用面板当前的右手 ready pose，不重新定义右手准备姿态。
本次仅完成代码与离线验证，未重启现场服务、ARM 或发送真实运动。

## 固定手型与直接控制

刚才记录的张开/握持已固定到 `config/rail_hand_presets.json`，原始会话文件不修改。
新版滑轨页启动时自动载入这两套预设，新建轨迹保留当前手型。
校验机器人模型、手指通道顺序和映射，不再因 D 环通用手型参数修改而跳过载入。
“覆盖保存张开手型 / 覆盖保存握持手型”明确确认后同时更新当前示教及持久默认值，下次启动仍保留。
加载其他示教文件时尊重该文件的手型，但不自动覆盖持久默认值。启动加载不会发送手部动作。

锁定或关闭手部 Web 后，直接点击滑轨页 **右手张开 / 右手握持**，确认后缓慢切换右手手指。
手臂必须停稳，可以处于手臂导纳或 ARMED_HOLD；不需要先退出导纳，也不会自动移动手臂。
等待状态显示手型到位，再开始拖动或录制。录制和执行期间不可切换。
切换会使旧计划及滑杆状态确认失效，正式执行前重新确认滑杆状态并规划。
STOP 或异常时停止切换并尝试保持当前手指，不自动张开、重试或退回。
面板无法锁定外部 Web 命令源，切勿同时使用两者控制手指。

以下流程中的“Web 调成已记录手型”现在均可直接使用上述两个按钮，无需再操作 Web。

## 新增：连续轨迹录制与关节插补

### 2026-09-18：独立 LowState 直采

录制通路改为 `/lowstate → 独立只读进程 → 原始文件`，不再从面板的 `/joint_states`
回调收集轨迹。原关节桥接仍供控制面板、MoveIt 和 RViz 使用，不修改控制网关或安全超时。
界面按钮不变：等待“LowState 直采录制中”后拖动，终点停稳后“结束并保存本段”。
录制进程直接检查 mode6/pr0、电机数据、关节范围、左臂变化、tick、DDS 源时间戳及接收间隔，
约 100 Hz 保存真实采样，不伪造中间测量点。面板卡顿不再触发原先基于面板反馈年龄的 100 ms 拒绝。
实际直采进程接收间隔或 DDS 源间隔超过 100 ms 仍拒绝；STOP、模式变化、手型及手部通信检查不取消。
因此这是隔离界面造成的延迟，不保证系统或物理网络永不出现断流。

每次录制的文件保存在会话下 `rail_recordings/<时间戳>_<轨迹段>/`：
- `request.json`：段名、关节映射、起点、限位及 STOP 代次。
- `samples.jsonl`：约 100 Hz 原始采样，含关节值、tick、DDS 源/接收时间戳、本机处理时间；约每 0.1 秒刷入文件。
- `status.json`：点数、时长、最大处理间隔与源时间间隔、完成/错误状态。
- `failure.json`：面板捕获的失败原因、手型读取证据和网关快照；进程自身异常还见 `receiver.log`。

失败或取消不覆盖旧的成功轨迹，已经写出的原始数据保留供排查；失败段不能直接重放。
结束时由独立进程核实最后 0.4 秒静止，再进行原有 2 mm 取点、插补和预览检查。
只需安全结束后重开面板加载新版，不必为了直采另起或重启机器人网关。

选择“路径来源 → 记录轨迹重放（关节插补）”。此模式不需要先记录旧 A/B 端点或接近关键点，
不估计抓取中心，也不把腕部直线当作抓取点直线。它回放导纳下实际记录的右臂与腰 yaw 关节路径。

### 双臂与腰 yaw 导纳、起点容差

要同时拖动腰，在静止保持时点击滑轨页“进入双臂＋腰 yaw 导纳”，确认支撑稳固，
等本页显示“腰 yaw 导纳：已启用”后再拖动。如果已经在仅手臂导纳中，先停稳，
点击“退出导纳，原地保持”，等 ARMED_HOLD 后再进入双臂＋腰 yaw 导纳。
腰 roll/pitch 不进入导纳。左臂虽然进入导纳，但本任务只记录右臂和腰 yaw，左臂关节仍需保持不动。
腰 yaw 不再受整段变化 0.5 度的限制；仍保留模型/网关角度范围、速度、加速度和反馈跳变检查。

准备位与每段接缝的对齐门槛改为 **20 mm / 5 度 / 0.15 rad**，三项都需满足。
起点手型读取期间允许最多 2 度关节变化，但实际开始录制时仍需停稳，以当时实测姿态开始记录。
报错会显示具体位移、姿态及关节偏差，不要求人工复刻到 1 mm。
容差内的差异不是忽略或瞬移：重放时生成限速补接，并在预览中显示。
握杆状态的补接不是接触力控制，必须核对其方向不会横向挤压滑轨；净空确认包含补接段。

### 录制后在 RViz 预览完整流程

1. 保持模式录齐四段，松手返回模式录齐六段，点击“导出”保存。
2. 在滑轨页选择“操作模式”，点击 **RViz 预览完整推入＋拉出（不执行）**。
3. 等待状态显示完整预览已发布。RViz 的 `Validated planned path - NOT measured state`
   轨迹显示订阅 `/g1/task/validated_path`，会循环播放机器人动画。
4. 动画包括右臂、腰 yaw、张开/握持及段间补接：准备位接近 A、抓握、推入 B，
   再按所选模式显示保持后拉出，或松手退出后重新接近 B 抓握拉出，最终松手返回准备位。
5. 单段仍可使用“检查 / 预览选中段”。整套预览不需要机器人实际回准备位、退出导纳或确认滑杆状态，
   不读取手部、不下发动作、不产生可执行计划；正式执行仍分别规划并下发推入和拉出。

半透明动画是模型路径，不是实机运动。手指几何是既有近似映射，滑杆实体及接触受力没有仿真。
固定的实机模型仍显示当前测量姿态。预览失败会说明缺少的轨迹段或具体偏差，不强行播放不连续路径。

已有文件兼容，张开/握持手型不清空。**已有手型时不要点击“新建滑轨示教”。**
本次只读核对到用户现有两套手型位于：
`data/task_sessions/20260917_134534_171344/rail_autosave/config.json`。
该文件未被本次开发修改。安全结束现场动作后加载新版面板，在滑轨页“加载”此文件即可继续。
原有自动备份路径随会话变化；若之后修改过手型，以自己最新导出的文件为准。

### 手型控制入口

- 滑轨页“右手张开 / 右手握持”：各段之间直接切换已保存手型。
- 手部 Web：仅在需要重新微调手型时使用；先解锁，调整右手，等手指停稳，再锁定。
  未勾“拖动时连续跟随”时，松开滑条仍会发送指令，不是仅预览。
- 滑轨页：读取手型，选择轨迹段，开始/结束录制，检查预览，规划推入/拉出。
- 录制中保持该段的手型不变，不操作 Web。手型反馈会定期检查，异常时该段拒绝保存。
  Web 锁定只锁网页操作，不停手部服务、不松手，也不阻止任务面板读取。

### 每段的统一操作

1. 在该段起点静止，处于 `TASK_ADMITTANCE`；需要拖腰时确认腰 yaw 导纳已启用，点击本页张开或握持按钮并等待到位。
2. 从“录制段”选择对应条目，点击“开始录制选中段”，确认提示。
3. **等待显示“录制中”后才拖动**。起点手型读取阶段尚未记录，不能提前移动。
4. 慢速、连续地拖动右臂完成该段，不必每 2 mm 停一次；尽量避免来回抖动和长时间停顿。
5. 到终点后停稳至少约 0.4 秒，再点击“结束并保存本段”。等待检查完成并显示“已保存”。
6. “检查 / 预览选中段”进行关节插补与限值检查，在 RViz 发布该段预览，**不能直接执行该段**。

表格显示原始样本数、取点数、腕部模型路径长度和记录状态。
“已录制”表示录制数据检查通过，不代表已完成重放插补检查或实机验收。
“取消本次录制”不发机器人停止/松手指令，只放弃本次录制；仍保持原导纳模式。
覆盖旧段前会提示，取消或失败保留旧段。记录成功自动保存，仍建议完成后点击“导出”。

### 首先录好保持模式的四段

1. 使用原有准备动作到现有右手准备位。进入“手臂导纳”，点击“右手张开”并等待到位。
   选择 **接近外端：准备位 → A**，开始录制，拖到外端可抓杆位置，停稳后结束保存。
2. 保持手臂在 A。点击“右手握持”，等待到位并核对实际握住杆部。
   选择 **握持推进：A → B**，开始录制，沿滑轨推到内端目标位置，停稳后结束保存。
   不继续顶压机械限位。
3. 保持在 B 握持，不张手。选择 **握持拉出：B → A**，开始录制，沿滑轨拉回外端，停稳后结束保存。
4. 保持手臂在 A。点击“右手张开”，等待到位并确认脱离杆部。
   选择 **外端退出：A → 准备位**，开始录制，安全退出并回准备位，停稳后结束保存。

这样已具备“推入后保持握持”模式所需四段。推入与拉出仍是两次独立下发，不自动循环。

### 再补齐松手返回模式的两段

1. 右手在准备位且张开，人工将滑杆放到内端 B，确认松手后不会回弹。
2. 选择 **接近内端：准备位 → B**，开始录制，张手接近 B 的抓握位置，停稳后结束保存。
   该段终点需要与已录“握持拉出”的起点一致。
3. 手保持张开，不必为了录退出段再次握紧。
   选择 **内端退出：B → 准备位**，开始录制，安全退出并回准备位，停稳后结束保存。
4. 导出整套数据。六段齐全后可使用两种模式，推入和拉出都使用各自实录路径，不自动反向代替。

### 正式规划与回放

1. 确认各段检查/预览合理；手臂已离开杆部，右手为记录的张开手型。
2. 锁定 Web，停止其他手部命令来源。“退出导纳，原地保持”只恢复原地保持，不会移动到准备位。
   需要时使用原有准备动作回准备位；该动作使用通用 open 手型，若与你记录的张开手型不同，
   必须在规划前点击本页“右手张开”调回记录值。
3. 人工将滑杆置于外端，选择“外端”，点击“确认滑杆当前状态”。
4. 选择操作模式，勾选 Web 停止发指令/工位固定/路径净空等确认项，点击“规划推入”。
5. 检查完整预览，在主面板勾选 `Path clear` 后点击对应执行按钮。规划本身不会运动。
6. 推入后，保持模式停在 B 并握住；松手返回模式会张手、走实录 B 退出段回准备位。
7. 需要拉出时，不改变所选模式，重新勾选确认项，点击“规划拉出”，检查预览后再执行。
   保持模式直接拉出；松手返回模式先走实录 B 接近段、握持，再拉出。最终张手并经 A 退出段回准备位。

首次使用、加载、STOP 或失败后需要重新核对真实滑杆状态。正常完整执行会更新流程状态，
但这是关节动作结果，不是独立的滑杆/抓握检测。没有自动回撤、松手或故障重试。

### 轨迹模式的采样与检查

- 原始数据由独立进程直接订阅 LowState，约 100 Hz 保留真实采样，含 DDS 源时间戳；不会把下发目标冒充实测值。
- 按累计腕部 FK 位移约 2 mm 取点，转角达到 0.5 度、关节变化达到 0.01 rad 时额外保留点；
  对转折处补保留原始点，不人为补造测量。2 mm 不是未知抓取中心的物理采样精度。
- 相邻原始反馈间隔超过 100 ms、位移超过 2 mm、转角超过 2 度或关节跳变过大时拒绝该段，要求慢速重录。
  左臂关节移动超过 0.025 rad、手型变化或 STOP/模式变化也拒绝保存；腰 yaw 随右臂同步记录。
- 每段限 5 分钟/30000 个原始样本。录制只读手反馈，不发送手型或运动命令。
- 以保留的实测关节点构造五次关节插补，阶段起止速度/加速度为零，内部点无需逐点停顿。
  重新安排时间以满足速度、加速度、jerk 和腰包络限制，不复现人工拖动的原始速度。
- 校验网关实际 Hermite 插值；相对原始记录的模型路径偏离超过 0.5 mm / 0.5 度 / 0.01 rad 时拒绝规划，
  不自动大幅平滑切角。原始样本之间的参考本身也只是关节插值，不是外部实测抓取点轨迹。
- 实际起点、阶段连接及回准备位允许 20 mm / 5 度 / 0.15 rad 内的对齐误差，使用单独的零速边界连接。
  这段连接也在预览中，超过范围拒绝，不自动规划大幅补接。“相对准备位/端点”读数可辅助导纳对齐。
- 本模式不要求推拉全过程的手腕朝向恒定；它记录并回放实际朝向变化，但不估计/补偿抓取中心。
- 初始腕部速度上限仍为 5 mm/s，关节速度/加速度比例 0.15；不用 D 环阶段高增益。
- 仅模型插值与离线流程验证，非接触力控、非防滑检测，未增加碰撞检测，也未完成实机验收。

## 旧端点示教（仍保留）

1. 固定机器人、支撑和滑轨。使用现有准备动作到右手准备位。
2. 在滑轨页进入手臂导纳；腰保持不动。等待网关 TASK_ADMITTANCE 后再拖动。
3. 用手部 Web 调好张开手型，等手指静止，点击“记录张开手型”。
   “读取右手反馈”仅刷新快照，不保存为手型，也不发送手型指令。
4. A 路径按“准备位 → 外端”的顺序逐个“追加接近关键点”。
   至少记录一个接近点。到外端抓握位置，用 Web 调好实际握杆手型，
   点击“记录握持手型”和“记录抓握端点”。
5. 保持相同握持姿态，手臂导纳下推到内端，选择 B 并记录抓握端点。
   不继续顶压机械限位。A/B 腰角和手腕朝向差均不得超过 0.5 度。
   接触段锁定起点腰角，用局部 IK 吸收示教腰反馈的微小差异，不让腰随滑杆推拉。
6. 松手后，另外按“准备位 → 内端”的顺序记录 B 接近关键点。
   可以先录端点后录路径；关键点列表始终按准备位到端点的方向排列。
   两端退出路径默认反向经过各自接近点，然后回准备位。
7. 示教修改自动备份到本次会话 `rail_autosave/config.json`；可导出/加载 JSON。
   删除错误点后重新追加；重录端点不会自动清空已录的接近点。

手型表使用六个归一化通道 [0, 1]，顺序为小指、无名指、中指、食指、拇指 2、拇指 1。
记录同时保存实测 `feedback_q` 和 Web 下发后的 `target_q`，回放以实测手型为位置目标；
鼠标悬停数值可查看记录时目标值。手型不是握力或防滑测量。
没有实现手指导纳，不要通过人工强掰手指示教。

## 执行

先停止 Web 的持续/周期下发。面板不能锁定外部 Web 控制源，不能让两个界面同时控制手。
退出手臂导纳并确认静止保持。使用现有准备动作到右手准备位，右手应为所记录的张开手型。
首次使用、加载、STOP 后或位置不确定时，人工核对并确认滑杆状态。

- **推入后保持握持**：规划推入 → 主面板核对 Path clear 并执行 → A 抓握、推到 B 后保持。
  之后单独规划拉出并执行 → B 拉回 A、松手、反向退出、回准备位。
- **推入后松手回准备位**：规划推入并执行 → A 抓握、推到 B、松手、B 路径退出、回准备位。
  之后单独规划拉出并执行 → B 路径接近、重新抓握、拉回 A、松手、A 路径退出、回准备位。

每次规划前确认 Web 停止发指令、工位固定、路径净空和松手后滑杆位置稳定。
推入与拉出始终是两个单独规划/执行动作，不自动衔接。
若切换模式，必须核对当前实际状态与所选模式的起点要求。
保持模式拉出要求机器人在 B 且右手与握持记录匹配；其他起点要求在现有右手准备位。
不满足时拒绝，不自动寻找滑杆或补接到起点。

## 旧端点模式的路径与边界

- 所有手臂段均为腕部参考点的分段笛卡尔直线，朝向平滑插值；不使用食指 TCP 或 A/B/C 视觉补偿。
- 每个示教关键点停稳，不自动切角。A↔B 接触段要求近似固定朝向和固定腰角。
- 初始腕部平移速度上限 5 mm/s，关节速度/加速度比例 0.15，仍受网关能力限制。
- 实际关节插值的 FK 校验：相对预期路径位置误差不超过 0.5 mm、姿态误差不超过 0.5 度。
  这是模型插值误差，不是实机绝对精度或接触测量。找不到合格连续 IK 时要求补录关键点。
- 关节限位余量 0.02 rad，保留速度、加速度、jerk、腰包络、反馈新鲜度、温度、力矩与 STOP 保护。
  滑轨执行的关节端点容差与拉环共用 `execution.endpoint_tolerance_deg`，当前为 1.432394 度（0.025 rad）；等待到位时间为 5 秒。首次起点检查、反馈新鲜度及受阻/STOP 保护不变。
- 不新增环境碰撞查询，完整路径与手型变化的净空由操作者确认；首次低速分段验证。
- 松手后滑杆必须自行保持位置；不能据关节到位推断已成功抓握或确实推动了滑杆。
- STOP/失败后状态待确认；不自动松手、回撤或重试。文件加载不恢复执行授权。
- 原 D 环阶段增益不会用于滑轨。运行中的旧面板不会自动加载这些 Python 修改。
  应在操作者安全结束现场任务后加载新版面板，不能在握持物体期间为了更新而关闭/重启。
